# Создание проекта Expo

## Создание проекта

### Системные требования:
   Node.js: необходима LTS-версия.
   Операционные системы: поддерживаются macOS, Windows (PowerShell и WSL 2) и Linux.

### Создание стандартного проекта
Рекомендуется использовать инструмент create-expo-app, который включает базовый пример кода для быстрого старта.
Основные команды для инициализации проекта:
-   npx create-expo-app@latest
-   yarn create expo-app
-   pnpm create expo-app
-   bun create expo
>Для выбора альтернативного шаблона можно добавить опцию ```--template```.

Для новичков: доступно создание первого приложения с помощью AI-агента без написания кода (руководство Build with AI).

### Использование готовых примеров
Вместо пустого или стандартного проекта можно начать с одного из официальных примеров Expo (Expo Router, Expo Widgets или работа с камерой).

## Настройка окружения для Expo

### Выбор устройства для разработки
Рекомендуется использовать физическое устройство, так как это позволяет видеть именно то, что увидят пользователи. Доступные варианты:
-   Физическое устройство Android.
-   Физическое устройство iOS.
-   Эмулятор Android (Android Emulator).
-   Симулятор iOS (iOS Simulator).

### Выбор способа разработки

1. Expo Go: бесплатное приложение-песочница для студентов и новичков, позволяющая быстро попробовать Expo и понять основы. Оно ограничено в функциональности и не подходит для создания полноценных продакшн-проектов, так как не поддерживает кастомные нативные модули.

2. Development Build: собственная сборка вашего приложения, включающая инструменты разработчика Expo. Поддерживает пользовательские нативные модули и предназначена для серьезных проектов.


## Начало разработки в Expo
### Запуск сервера разработки
Для запуска локального сервера разработки надо выполнить следующую команду в терминале:
```
npx expo start
```
### Открытие приложения на устройстве
После запуска команды в терминале отобразится QR-код. 

Подключение:
Отсканируйте QR-код камерой или приложением Expo Go. 
Эмулятор / Симулятор: нажмите клавишу A (для Android Emulator) или I (для iOS Simulator) прямо в терминале.
>__Проблемы?__ Убедитесь, что вы находитесь в одной сети __Wi-Fi__ на вашем компьютере и вашем устройстве. Если он все еще не работает, это может быть связано с конфигурацией маршрутизатора — это характерно для общедоступных сетей. Вы можете обойти это, выбрав тип соединения __туннеля__ ```npx expo start --tunnel``` при запуске сервера разработки, а затем снова сканировать QR-код.

>Использование типа соединения __туннеля__ сделает перезагрузку приложения значительно медленнее, чем на __LAN__ или __LocalLocal__, поэтому лучше избегать туннеля, когда это возможно. Вы можете установить и использовать эмулятор или симулятор для ускорения разработки, если __для__ доступа к вашей машине с другого устройства в вашей сети требуется __Tunnel__.
### Внесение первых изменений
Откройте файл src/app/index.tsx для внесения изменений.

Пример:
```
     <ThemedView style={styles.heroSection}>
       <Анималый икона />
       <ThemedText type="title" style={styles.title}>
          Добро пожаловать в &nbsp;
          Здравствуйте, Мир!
       </ThemedText>
     </ThemedView>
```
#### Если изменения не отображаются на устройстве: 

По умолчанию Expo использует функцию Fast Refresh (быстрое обновление) для автоматической перезагрузки приложения при сохранении файла. Если этого не происходит:

Убедитесь, что режим разработки включен в Expo CLI. Полностью закройте приложение Expo Go и откройте его снова. Встряхните устройство (или нажмите Cmd ⌘ + D на iOS / Cmd ⌘ + M или Ctrl + M на Android), чтобы открыть меню разработчика. Найдите пункт Fast Refresh: если он выключен (Enable Fast Refresh), включите его; если он уже включен (Disable Fast Refresh), просто закройте меню и попробуйте изменить код снова.

### Следующие шаги в Expo
#### Сбросить свой проект
Вы можете удалить код шаблона и начать все заново с новым проектом. Запустите следующую команду для сброса вашего проекта:

    npm run reset-project
>Эта команда переместит существующие файлы в приложении в app-пример, а затем создаст новый каталог приложений с новым файлом index.tsx.

#### Разработка, обзор и развертывание
Узнайте как развиваться, читая документы в разделе «Разработка».

После того, как вы разработали свое приложение, вы можете поделиться им со своими товарищами по команде для review-обзора.

Наконец, вы можете создавать и отправлять свой проект в магазины приложений.

# Создание первого приложения на Expo

Добро пожаловать в пошаговое руководство по созданию вашего первого мобильного приложения с использованием фреймворка Expo! В этом туториале мы вместе построим приложение **StickerSmash** с самого начала, разбирая каждый шаг подробно и понимая, что именно происходит на каждом этапе разработки.

Expo — это мощный инструмент, который значительно упрощает процесс разработки приложений на React Native, позволяя сосредоточиться на создании функциональности, а не на настройке окружения.

## 📋 Предварительные требования

Прежде чем мы приступим к созданию приложения, необходимо убедиться, что на вашем компьютере установлены все необходимые инструменты. Это важный этап, который обеспечит бесперебойную работу в процессе разработки.

### Что нужно установить:

1. **Node.js (LTS-версия)**
   
   Node.js — это среда выполнения JavaScript, которая необходима для работы Expo и всех связанных с ним инструментов. Рекомендуется устанавливать именно LTS-версию (Long Term Support), так как она является наиболее стабильной и проверенной.
   
   - Скачайте установщик с официального сайта [nodejs.org](https://nodejs.org/)
   - Выберите версию с пометкой "LTS"
   - После установки проверьте корректность, выполнив команду: `node --version`

2. **Редактор кода**
   
   Для написания кода вам понадобится удобный редактор. Хотя можно использовать любой текстовый редактор, мы настоятельно рекомендуем **Visual Studio Code** (VS Code), так как он:
   
   - Бесплатный и имеет огромную экосистему расширений
   - Отлично поддерживает TypeScript и JavaScript
   - Имеет встроенный терминал
   - Предоставляет удобную автодополнение и подсветку синтаксиса
   
   Альтернативы: WebStorm, Sublime Text, Atom или любой другой редактор на ваш выбор.

3. **Expo Go на мобильном устройстве**
   
   Expo Go — это приложение, которое позволяет запускать ваш Expo-проект на реальном мобильном устройстве без необходимости компиляции нативного кода. Это значительно ускоряет процесс разработки и тестирования.
   
   - **Для Android:** скачайте из Google Play Store
   - **Для iOS:** скачайте из App Store
   
   Приложение бесплатное и не требует регистрации.

##  Создание проекта

Теперь, когда все необходимые инструменты установлены, мы можем перейти к самому интересному — созданию нашего первого проекта!

### Инициализация приложения

Для создания нового Expo-приложения мы будем использовать утилиту командной строки `create-expo-app`. Этот инструмент автоматически настроит все необходимые зависимости и создаст структуру проекта, готовую к разработке.

Откройте терминал (командную строку) и перейдите в директорию, где вы хотите создать свой проект. После этого выполните следующую команду:

```bash
# Создание проекта с именем StickerSmash
npx create-expo-app@latest StickerSmash
```

Давайте разберем, что означает каждая часть этой команды:
npx — это инструмент, который позволяет запускать пакеты npm без их глобальной установки. Он временно загружает и выполняет нужную утилиту.
```create-expo-app@latest``` — указывает на использование последней версии инструмента для создания Expo-приложений.
StickerSmash — это имя вашего проекта. Вы можете выбрать любое другое название, но в этом туториале мы будем использовать именно его.
После выполнения команды CLI (интерфейс командной строки) предложит вам выбрать версию Expo SDK. Выберите SDK 57 (или актуальную версию на момент чтения), используя стрелки на клавиатуре и нажав Enter.

```bash
Select an Expo SDK version > SDK 57
```

После создания проекта не забудьте перейти в его директорию:

```bash
# Переход в директорию созданного проекта
cd StickerSmash
```

Альтернативные способы создания проекта
Если вы предпочитаете использовать другие менеджеры пакетов вместо npm, Expo поддерживает и их:
Для пользователей Yarn:

```bash
yarn create expo-app StickerSmash
cd StickerSmash
```

Для пользователей pnpm:

```bash
pnpm create expo-app StickerSmash
cd StickerSmash
```

Для пользователей Bun:

```bash
bun create expo StickerSmash
cd StickerSmash
```

Все эти команды выполняют одну и ту же задачу — создают новый Expo-проект с идентичной структурой. Выбор инструмента зависит исключительно от ваших личных предпочтений.

### Почему стоит использовать шаблон по умолчанию?

Шаблон, который создается при инициализации проекта, не случаен. Он включает в себя тщательно подобранный набор инструментов и конфигураций, которые облегчат вашу разработку:


Создаёт React Native проект с установленным пакетом expo — вам не нужно вручную настраивать базовую конфигурацию, всё уже готово к работе.
Включает рекомендуемые инструменты (Expo CLI) — командный интерфейс Expo предоставляет множество полезных команд для разработки, сборки и публикации приложения.


Содержит навигатор на основе Expo Router — современная система навигации, основанная на файловой структуре, что делает создание экранов интуитивно понятным.


Автоматическая настройка для Android, iOS и Web — один код работает на всех платформах без необходимости дополнительной настройки.


TypeScript настроен по умолчанию — вы получаете все преимущества статической типизации из коробки, что помогает избегать ошибок и улучшает автодополнение в редакторе.


### Загрузка и настройка ресурсов

В процессе разработки нам понадобятся графические ресурсы (изображения, иконки и т.д.). Для удобства их можно скачать в виде готового архива.

Эти ресурсы будут использоваться на протяжении всего туториала, поэтому важно подготовить их заранее.


### Сброс шаблона проекта

По умолчанию Expo создает проект с демонстрационным кодом, который показывает различные возможности фреймворка. Однако для обучения лучше начать с чистого листа, чтобы понять, как всё работает с нуля.
Для этого существует специальный скрипт reset-project, который удаляет весь демонстрационный код, оставляя только минимально необходимую структуру.
Выполнение сброса
В терминале, находясь в директории проекта, выполните:

```bash
npm run reset-project
```

Если вы используете другие менеджеры пакетов:

```bash
# Yarn
yarn run reset-project

# pnpm
pnpm run reset-project

# Bun
bun run reset-project
```

### Что происходит при выполнении скрипта?

Скрипт ```reset-project``` выполняет несколько важных действий:
1. Сбрасывает структуру директории src/app — удаляет все демонстрационные экраны и компоненты
2. Перемещает файлы из директории src (включая папки components, constants, hooks) в специальную папку example. Эта папка больше не участвует в работе приложения, и вы можете смело удалить её, чтобы не захламлять проект.
3. Оставляет только необходимые файлы:
    1. index.tsx — главный экран приложения
    2. _layout.tsx — файл конфигурации навигации

Теперь у вас есть чистый проект, в котором вы сами будете создавать все компоненты и экраны. Это лучший способ понять архитектуру Expo и React Native.

## Запуск приложения

После того как проект создан и очищен от шаблонного кода, самое время запустить его и увидеть результат!

### Запуск сервера разработки

Expo предоставляет удобный сервер разработки, который компилирует ваш код в реальном времени и позволяет мгновенно видеть изменения на устройстве.
Для запуска сервера выполните в терминале:

```bash
npx expo start
```

Если вы используете другие менеджеры пакетов:

```bash
# Yarn
yarn expo start

# pnpm
pnpm expo start

# Bun
bun expo start
```

### Что происходит после запуска?

После выполнения команды вы увидите следующее:
1. Запускается сервер разработки — в терминале появится информация о статусе запуска
2. Отображается QR-код — этот код содержит информацию о том, как подключиться к вашему приложению
3. Появляется меню с опциями — вы можете выбрать, на какой платформе запустить приложение

### Как запустить на разных платформах

#### Мобильное устройство (Android)

1. Убедитесь, что ваш телефон и компьютер подключены к одной Wi-Fi сети
1. Откройте приложение Expo Go на телефоне
1. Выберите опцию "Scan QR code" (Сканировать QR-код)
1. Наведите камеру на QR-код в терминале
1. Приложение автоматически загрузится и запустится

#### Мобильное устройство (iOS)

1. Убедитесь, что ваш iPhone и компьютер подключены к одной Wi-Fi сети
1. Откройте стандартное приложение Camera (Камера)
1. Наведите камеру на QR-код в терминале
1. Нажмите на появившееся уведомление
1. Приложение откроется в Expo Go

#### Веб-версия

Если вы хотите увидеть, как ваше приложение выглядит в браузере:
1. Нажмите клавишу W (от слова "Web") в терминале, где запущен сервер
1. Браузер автоматически откроется и загрузит веб-версию приложения
1. Вы можете взаимодействовать с приложением как с обычным сайтом

Это особенно удобно для быстрой проверки интерфейса без необходимости использования эмулятора или физического устройства.

## Редактирование главного экрана

Теперь, когда приложение запущено, давайте научимся вносить изменения в его интерфейс.

### Что такое index.tsx?

Файл src/app/index.tsx — это точка входа вашего приложения. Именно этот файл выполняется первым при запуске приложения. Он определяет, что пользователь увидит на главном экране.
В текущем состоянии файл содержит базовый код с использованием стандартных компонентов React Native:
  ```
  <View> — аналог <div> в HTML, контейнер для других компонентов
  <Text> — компонент для отображения текста
  ```

### Стили в React Native

Важно понимать, что стилизация в React Native отличается от веб-разработки:

+ Не используется CSS — вместо CSS-файлов стили задаются через JavaScript-объекты
+ StyleSheet.create() — специальный метод для создания оптимизированных стилей
+ Свойства похожи на CSS — если вы знакомы с веб-разработкой, многие свойства будут вам знакомы (например, backgroundColor, color, alignItems)
+ CamelCase — свойства пишутся в camelCase (например, backgroundColor вместо background-color)

### Практическое задание: модификация экрана

Давайте изменим внешний вид главного экрана, добавив свои стили и текст.

#### Шаг за шагом:

1. Откройте файл src/app/index.tsx в вашем редакторе
2. Импортируйте StyleSheet — добавьте в импорт из react-native:

```typescript
import { Text, View, StyleSheet } from 'react-native';
```

3. Измените содержимое компонента — замените текст внутри <Text> на "Home screen"
4. Добавьте стили — создайте объект styles после компонента

# Добавление навигации в приложение Expo

Добро пожаловать во вторую часть нашего путешествия по созданию приложения **StickerSmash**! В предыдущем разделе мы настроили базовое окружение и создали главный экран. Теперь пришло время оживить наше приложение, добавив возможность перемещения между разными экранами. 

В экосистеме Expo для этих целей используется **Expo Router** — мощный, современный и интуитивно понятный фреймворк маршрутизации, основанный на файловой системе. Он позволяет создавать навигацию, которая работает одинаково хорошо на iOS, Android и в веб-браузере, используя единый код.

---

## Основы Expo Router

Прежде чем писать код, давайте разберем ключевые концепции и соглашения об именовании файлов, на которых строится работа Expo Router. Понимание этих правил сделает вашу разработку предсказуемой и логичной.

### Ключевые концепции:

1. **Директория `app`**  
   Это специальная папка (в нашем случае `src/app`), которая содержит **только** маршруты (экраны) и их макеты (layouts). Любой файл, добавленный в эту директорию, автоматически становится экраном в мобильном приложении и страницей в веб-версии. Вам больше не нужно вручную регистрировать экраны в конфигурационных файлах!

2. **Корневой макет (`Root Layout`)**  
   Файл `src/app/_layout.tsx` является точкой входа для всей навигации. Он определяет общие элементы пользовательского интерфейса (например, заголовки или нижние панели вкладок), которые должны оставаться неизменными при переходе между разными маршрутами.

3. **Соглашения об именах файлов**  
   - Файлы с именем `index.tsx` соответствуют родительской директории и **не добавляют** новый сегмент к пути. Например, `src/app/index.tsx` соответствует корневому маршруту `/`.
   - Файл маршрута должен экспортировать React-компонент как значение по умолчанию (`export default`).
   - Поддерживаются расширения `.js`, `.jsx`, `.ts` и `.tsx`.

4. **Единая структура навигации**  
   Android, iOS и веб используют одну и ту же файловую структуру для построения навигации, что гарантирует консистентность поведения приложения на всех платформах.

## Шаг 1: Добавление нового экрана в стек

Для начала создадим простой второй экран, чтобы нам было куда переходить. Мы назовем его "About" (О приложении).

### Создание файла `about.tsx`

Создайте новый файл с именем `about.tsx` внутри директории `src/app`. Этот файл будет отображать название экрана, когда пользователь перейдет по маршруту `/about`.

```typescript
// src/app/about.tsx
import { Text, View, StyleSheet } from 'react-native';

export default function AboutScreen() {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>About screen</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    justifyContent: 'center',
    alignItems: 'center',
  },
  text: {
    color: '#fff',
  },
});
```

### Настройка заголовков в `_layout.tsx`

Теперь нам нужно сообщить нашему корневому макету о существовании новых экранов и задать им понятные заголовки, которые будут отображаться в верхней части экрана (в хедере).

Откройте файл `src/app/_layout.tsx` и обновите его содержимое:

```typescript
// src/app/_layout.tsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack>
      {/* Настраиваем заголовок для главного экрана */}
      <Stack.Screen name="index" options={{ title: 'Home' }} />
      {/* Настраиваем заголовок для экрана About */}
      <Stack.Screen name="about" options={{ title: 'About' }} />
    </Stack>
  );
}
```

> **Что такое Stack (Стек)**?
Стек-навигатор — это фундаментальный способ перемещения между экранами. Он работает по принципу стопки карт:
На Android новый экран плавно появляется поверх текущего (снизу вверх).
На iOS новый экран выезжает справа.
Expo Router предоставляет компонент `<Stack>`, который автоматически управляет этой анимацией и историей переходов (кнопка "Назад").

## Шаг 2: Навигация между экранами

Теперь, когда у нас есть два экрана, давайте создадим кнопку для перехода между ними. В Expo Router для этого используется компонент `<Link>`, который работает аналогично тегу `<a>` в веб-разработке, но адаптирован под мобильные платформы.

### Модификация главного экрана

Откройте `src/app/index.tsx` и внесите следующие изменения:

1. Импортируйте компонент `Link` из библиотеки `expo-router`.
1. Добавьте компонент `<Link>` после текста, указав в пропсе `href` целевой маршрут (`/about`).
1. Добавьте стили, чтобы ссылка выглядела как интерактивная кнопка (используя те же свойства, что и у `<Text>`).

```typescript
// src/app/index.tsx
import { Text, View, StyleSheet } from 'react-native';
import { Link } from 'expo-router'; // 1. Импорт Link

export default function Index() {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>Home screen</Text>
      
      {/* 2. Добавление компонента Link с указанием пути */}
      <Link href="/about" style={styles.button}>
        Go to About screen
      </Link>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    alignItems: 'center',
    justifyContent: 'center',
  },
  text: {
    color: '#fff',
  },
  // 3. Стилизация ссылки
  button: {
    fontSize: 20,
    textDecorationLine: 'underline',
    color: '#fff',
    marginTop: 20, // Небольшой отступ для красоты
  },
});
```

Сохраните файл, и благодаря функции Hot Reload вы мгновенно увидите подчеркиваемый текст на экране. При нажатии на него приложение плавно перейдет на экран "About", а в заголовке появится кнопка возврата назад.

## Шаг 3: Добавление маршрута "Не найдено" (404)

Что произойдет, если пользователь попытается перейти по несуществующему адресу (например, `/random-page`)? По умолчанию это может привести к крашу приложения или отображению стандартной, некрасивой веб-ошибки.

Expo Router предоставляет элегантное решение: специальный файл `+not-found.tsx`.

### Создание экрана ошибки

1. Создайте файл с именем `+not-found.tsx` (именно с плюсом в начале) в директории `src/app`.
1. Используйте компонент `<Stack.Screen>` для задания заголовка этой страницы.
1. Добавьте компонент `<Link>`, чтобы пользователь мог легко вернуться на главный экран.

```typescript
// src/app/+not-found.tsx
import { View, StyleSheet } from 'react-native';
import { Link, Stack } from 'expo-router';

export default function NotFoundScreen() {
  return (
    <>
      {/* Устанавливаем кастомный заголовок для страницы ошибки */}
      <Stack.Screen options={{ title: 'Oops! Not Found' }} />
      <View style={styles.container}>
        <Link href="/" style={styles.button}>
          Go back to Home screen!
        </Link>
      </View>
    </>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#25292e',
    justifyContent: 'center',
    alignItems: 'center',
  },
  button: {
    fontSize: 20,
    textDecorationLine: 'underline',
    color: '#fff',
  },
});
```

>Как протестировать: Запустите веб-версию приложения (нажмите W в терминале) и вручную введите в адресную строку браузера несуществующий путь, например: `http://localhost:8081/123`. Вы увидите ваш кастомный экран с кнопкой возврата!

## Шаг 4: Внедрение нижнего таб-навигатора (Bottom Tab Navigator)

Стек-навигация отлично подходит для последовательных переходов, но для основных разделов приложения (как в Instagram, Telegram или X) стандартом де-факто является нижняя панель вкладок (Tab Bar).

Мы сгруппируем наши экраны index и about внутри специальной директории, чтобы они отображались как вкладки, а не как отдельные страницы стека.

### Реорганизация структуры файлов

1. Внутри директории src/app создайте новую папку с именем (tabs).
    >Скобки в названии папки означают, что это "Route Group" (группа маршрутов). Она позволяет логически группировать файлы и применять к ним общий макет, не добавляя слово "tabs" в URL-путь.
1. Переместите файлы index.tsx и about.tsx внутрь папки (tabs).
1. Внутри папки (tabs) создайте новый файл _layout.tsx.

Теперь ваша структура должна выглядеть так:

```text
src/
└── app/
    ├── _layout.tsx         # Корневой макет (управляет всем)
    ├── +not-found.tsx      # Экран ошибки 404
    └── (tabs)/             # Группа маршрутов для табов
        ├── _layout.tsx     # Макет specifically для табов
        ├── index.tsx       # Маршрут '/'
        └── about.tsx       # Маршрут '/about'
```

### Настройка корневого макета

Обновите `src/app/_layout.tsx`, чтобы он указывал на нашу новую группу `(tabs)` и скрывал стандартный заголовок стека (поскольку заголовками теперь будут управлять табы).

```typescript
// src/app/_layout.tsx
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    <Stack>
      {/* headerShown: false скрывает верхнюю панель стека для табов */}
      <Stack.Screen name="(tabs)" options={{ headerShown: false }} />
    </Stack>
  );
}
```

### Настройка макета табов

Теперь наполните файл `src/app/(tabs)/_layout.tsx` логикой нижней панели:

```typescript
// src/app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router';

export default function TabLayout() {
  return (
    <Tabs>
      <Tabs.Screen name="index" options={{ title: 'Home' }} />
      <Tabs.Screen name="about" options={{ title: 'About' }} />
    </Tabs>
  );
}
```
Сохраните изменения, и вы увидите, что внизу экрана появилась стандартная нижняя панель с двумя вкладками!

## Шаг 6: Глубокая кастомизация таб-навигатора

Придадим нашим табам профессиональный вид, соответствующий темной теме нашего приложения. Мы добавим иконки, которые меняются в зависимости от активности вкладки, и перекрасим панели в наш фирменный темно-серый цвет (`#25292e`).

```typescript
// src/app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router';
import Ionicons from '@expo/vector-icons/Ionicons';

export default function TabLayout() {
  return (
    <Tabs
      screenOptions={{
        // Цвет активной иконки и текста вкладки
        tabBarActiveTintColor: '#ffd33d',
        
        // Стилизация верхнего заголовка (хедера)
        headerStyle: {
          backgroundColor: '#25292e',
        },
        headerShadowVisible: false, // Убираем некрасивую тень под хедером
        headerTintColor: '#fff',    // Цвет текста в заголовке
        
        // Стилизация самой нижней панели табов
        tabBarStyle: {
          backgroundColor: '#25292e',
        },
      }}
    >
      <Tabs.Screen
        name="index"
        options={{
          title: 'Home',
          // Функция рендеринга иконки. Получает состояние focused и цвет
          tabBarIcon: ({ color, focused }) => (
            <Ionicons 
              name={focused ? 'home-sharp' : 'home-outline'} 
              color={color} 
              size={24} 
            />
          ),
        }}
      />
      <Tabs.Screen
        name="about"
        options={{
          title: 'About',
          tabBarIcon: ({ color, focused }) => (
            <Ionicons 
              name={focused ? 'information-circle' : 'information-circle-outline'} 
              color={color} 
              size={24}
            />
          ),
        }}
      />
    </Tabs>
  );
}
```

### Разбор пропсов кастомизации:

+ `tabBarActiveTintColor`: Задает яркий желтоватый цвет (`#ffd33d`) для активной вкладки, чтобы пользователь четко понимал, где он находится.
+ `headerStyle` и `tabBarStyle`: Устанавливают одинаковый темный фон (`#25292e`) для верхней и нижней панелей, создавая ощущение целостного дизайна.
+ `headerShadowVisible: false`: Убирает стандартный разделитель (тень) между хедером и контентом на iOS, что делает интерфейс более современным и плоским.
+ `tabBarIcon`: Принимает функцию, которая возвращает компонент иконки. Мы используем тернарный оператор, чтобы показывать "залитую" (`sharp`) иконку, когда вкладка активна, и "контурную" (`outline`), когда она неактивна.
